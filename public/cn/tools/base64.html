Tool Documentation & Usage Guide

Base64 是一种将二进制数据转换为 ASCII 字符集的编码方案。它通常被用于在不支持处理二进制数据的纯文本媒介（如 HTML、XML、电子邮件等）上传输媒体数据。

为什么要使用 Base64 编码？

  • 保障数据完整性: 避免二进制媒体文件在经过文本协议传输时因编码转义导致数据损坏。
  • 内嵌媒体资源: 网页开发者经常将较小的图标或小字体文件转换为 Base64 直接写进 CSS 代码中，借此减少页面的 HTTP 连接请求次数。

常见问题解答

问：为什么 Base64 编码会让文件体积增大 33%？
答：Base64 把每 3 个源字节（24 位）映射成 4 个 ASCII 字符（每个 6 位）。因为用 4 个输出字节表示 3 个输入字节，编码后的体积就是原来的 4/3，即精确膨胀 33.33%。

问：用 Base64 编码来保护密码或私密数据安全吗？
答：不安全。Base64 是一种编码格式，不是加密方法。任何人都能在一行代码内把 Base64 字符串瞬间解码回原样，无需任何密码。绝不要用 Base64 来隐藏密码、API 密钥或令牌。

问：这个 Base64 工具如何保护我的数据隐私？
答：转换完全在你的浏览器内用 JavaScript 完成。任何文本都不会发送到任何服务器，你输入或粘贴的内容不可能被记录、存储或泄露。你输入的内容不会被存储。

问：Base64 如何处理 Unicode 和特殊字符？
答：标准的 JavaScript btoa() 只接受 Latin-1 二进制字符串（每字符一字节，0 到 255）。要编码中文或表情等 Unicode 字符，我们的工具会先经过 encodeURIComponent()，再把百分号编码映射回单字节后再做 Base64，从而保证完全 Unicode 安全。

问：我应该在什么场景下内联 Base64？
答：内联适合很小、很少变动且阻塞渲染的资源，比如图标、加载动画、邮件模板里的 logo。大图、希望浏览器独立缓存的内容，以及首屏主图都应避免内联，因为嵌入会阻碍并行下载并拖慢 HTML/CSS 解析。
