Git 撤销最后一次提交 — 三种安全做法

git reset --soft HEAD~1

保留，仍在暂存区

git reset HEAD~1

保留，退回未暂存

git reset --hard HEAD~1

删除

三种 reset 的区别

命令提交里的改动适用场景
git reset --soft HEAD~1保留，仍在暂存区想换提交信息或重新分组
git reset HEAD~1保留，退回未暂存想重新挑选要提交的内容
git reset --hard HEAD~1删除这次提交本身就是废的，内容也不要了

相关操作

命令作用
git commit --amend -m "更好的说明"改写最后一次提交，而不是撤销
git reflog时光机 — 找出 HEAD 曾经指向的任何提交
git revert <sha>撤销已经推送的提交（共享分支上安全）

撤销最后一次提交有三种方式，区别在于你的改动会变成什么状态。按你想保留多少来选。

常见问题

我误跑了 --hard，工作没了吗？
通常还在。git reflog 会列出 HEAD 走过的每个位置，找到 reset 之前的那次提交，再 git reset --hard HEAD@{n} 回去。reflog 一般保留约 90 天。

能用 reset 撤销已推送的提交吗？
不要。改写共享历史会逼所有人修自己的 clone。用 git revert ，它会新建一次提交把旧的抵消掉。

reset 和 revert 一句话区别？
reset 改写历史（只适合本地）；revert 追加历史（可以共享）。
