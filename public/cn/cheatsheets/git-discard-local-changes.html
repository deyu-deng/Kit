Git 丢弃本地改动 — 安全且彻底

git restore <file>

丢弃单个文件的改动

丢弃整个工作区的改动

git restore --staged <file>

保留改动，只把它移出暂存区

已跟踪文件（改过但没提交）

命令作用
git restore <file>丢弃单个文件的改动
git restore .丢弃整个工作区的改动
git restore --staged <file>保留改动，只把它移出暂存区

未跟踪文件（Git 没在管的新文件）

命令作用
git clean -n试运行 — 列出会被删掉的东西（永远先跑这个）
git clean -fd删除未跟踪的文件和目录
git clean -fdx连被忽略的文件一起删（node_modules、.env…）— 格外小心

丢弃未提交的工作是 Git 里少数没有内置撤销的操作，所以值得弄清楚每个命令到底扔掉什么。

常见问题

restore 和以前的 checkout -- 有什么区别？
效果一样。restore 是 Git 2.23 引入的，用来拆分 checkout 身上过多的职责；checkout 还能用，但 restore 语义更清楚。

丢弃的改动还能恢复吗？
已跟踪文件：有时可以，用 git fsck --lost-found 找悬空对象，或者看编辑器的本地历史。clean 删掉的未跟踪文件：基本没了，除非编辑器留了副本。

只想丢弃文件里的一部分改动？
git restore -p 会逐块问你，每块 y/n。
